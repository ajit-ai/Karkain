# v1.2.34 follow-up — portable signal control (baseline)

Status: **BASELINE**. The builtin/stdlib slice is complete (PR #68); signals,
dynamic-library boundary and further filesystem metadata were explicitly
deferred in `V1.2.34-TAKEOVER-BASELINE.md` §5. This slice takes only signals.

## 1. Measured current state

- `runtime/osctl/c/karkain_osctl.h` includes `<signal.h>` but declares **no
  signal function**; the C file implements none.
- `stdlib/process/process.kark` exposes `proc_spawn_pid`, `proc_kill_pid`,
  `proc_wait_pid`, `proc_pid`, `proc_is_running`, `proc_exit` — no signal API.
- `docs/audit/V1.2.34-TAKEOVER-BASELINE.md` §5 lists signals as a named
  follow-up, not an oversight.

So the language can start, kill and wait for processes but cannot change or
observe signal disposition.

## 2. Scope (smallest useful portable surface)

Three C23 builtins behind the existing `osctl_*` internal naming convention:

| Builtin | Meaning | Return |
|---|---|---|
| `osctl_sig_ignore(sig)` | set disposition to ignore | 0 on success, -1 on failure |
| `osctl_sig_default(sig)` | restore default disposition | 0 / -1 |
| `osctl_sig_raise(sig)` | deliver a signal to the current process | 0 / -1 |

Portability: C's `signal()` / `raise()` from `<signal.h>` exist on both the
Win32 CRT and POSIX. Common numbers match (SIGINT 2, SIGTERM 15). Unknown
signal numbers are refused by the runtime with a named error through the
existing `osctl` error string, never silently ignored.

Public stdlib names in `std.process`: `proc_ignore_signal`,
`proc_default_signal`, `proc_raise_signal` — wrappers keep the public API
style and call the internal builtins, so Phase 83 shadowing cannot recurse.

## 3. Boundaries

- No new link library. No handler callbacks: only ignore/default/raise, which
  are expressible without user code running inside a signal handler.
- Native and WASM refuse these builtins by name (K145/K108), consistent with
  the other osctl builtins; their feature-matrix rows must be added.
- `sig_raise(SIGKILL/SIGSTOP)` cannot be caught; the gate uses SIGINT after
  `sig_ignore`, which is defined and portable.
- This is not a general signal-handling model; no `sigaction`, no masks.

## 4. Evidence rule

The generated kcc mirror must stay fresh (`TestOSCtlKarkFresh`). The gate
must verify both engines print identical output for ignore→raise→survive and
that native/WASM refuse by name with no image. No claim of full signal
semantics beyond the three operations above.

  `implicit declaration of 'raise'`).
