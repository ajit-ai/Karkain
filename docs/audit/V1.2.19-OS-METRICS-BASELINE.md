# v1.2.19 — OS metrics / process enumeration

**Verdict: COMPLETE for the C23 path.** Both front ends can query real OS
metrics and enumerate processes through importable `std.os` wrappers. Native
and WASM remain excluded by existing process/socket/stdlib boundaries.

## 1. Measured baseline

- No OS metric, PID, CPU-count, memory or process-enumeration builtin existed
  in Go, kcc, native or WASM. The only process-like builtin was
  `system(cmd) -> int`, which cannot capture output.
- `stdlib/process`, `stdlib/env`, `stdlib/time`, `stdlib/log`, `stdlib/config`
  and `stdlib/system` were shell/PowerShell-backed, source-only or UNVERIFIED;
  `std.os` was listed as Planned and no `stdlib/os/` directory existed.
- Internal-only host metrics existed (scheduler CPU count, profiler QPC,
  bootstrap RAM probe) but were not reachable from `.kark`.
- Host library check: MinGW has `tlhelp32.h`, `sysinfoapi.h`,
  `processthreadsapi.h`, `libkernel32.a`; Linux CI has `unistd.h`,
  `dirent.h`, `/proc/meminfo` and `clock_gettime` under the existing
  `-D_POSIX_C_SOURCE=200809L`. **No new link library is required** on either
  supported path. macOS has no `/proc`; its documented boundary is below.

## 2. What changed

### Runtime, single source of truth
- `runtime/osmetrics/c/karkain_osmetrics.{h,c}` defines seven builtins:
  `karkain_os_pid`, `karkain_os_cpu_count`, `karkain_os_total_mem_mb`,
  `karkain_os_available_mem_mb`, `karkain_os_uptime_ms`,
  `karkain_os_process_list`, `karkain_os_last_error`.
- Windows: `GetCurrentProcessId`, `GetSystemInfo`, `GlobalMemoryStatusEx`,
  `GetTickCount64`, `CreateToolhelp32Snapshot`/`Process32FirstW/NextW`.
- POSIX: `getpid`, `sysconf(_SC_NPROCESSORS_ONLN)`, `/proc/meminfo`,
  `clock_gettime(CLOCK_MONOTONIC)`, `opendir("/proc")` + `comm`, capped at
  64 entries and sorted. The current PID is always reserved a slot and
  included, so the "list contains self" property is deterministic.
- macOS: `hw.memsize` via `sysctlbyname`; available memory returns -1 and the
  process list contains only the current process. This is a documented
  limitation, not a silent fake.
- `runtime/osmetrics/embed.go` embeds the C sources for Go;
  `scripts/gen-osmetrics-runtime.ps1` generates
  `src/compiler/osmetrics_runtime.kark` for kcc (never hand-edited);
  `pkg/codegen/osmetrics_kark_fresh_test.go` (`TestOSMetricsKarkFresh`) pins
  the mapping.

### Builtins and generation
- The seven `os_*` names are registered in the Go resolver, both kcc
  checker/sema tables and both C dispatchers.
- `needsOS` prescan gates emission: metric-free programs (including the
  bootstrap compiler) keep their exact historical preamble and link flags.
  The Go split flow carries `SplitResult.NeedsOS` into the shared header just
  as it carries `NeedsTLS`, avoiding the v1.2.17 imported-module defect.
- `OSLibFlags()` is an explicit empty seam — the platform calls already live
  in kernel32/libc.

### Library surface
- New canonical `stdlib/os/os.kark` with wrappers `os_current_pid`,
  `os_cpu_total`, `os_memory_total_mb`, `os_memory_available_mb`,
  `os_uptime`, `os_processes`, `os_error`. Wrapper names deliberately differ
  from builtin names so a wrapper cannot resolve to itself.
- Shell-backed `stdlib/process` and `stdlib/system` are left untouched; this
  slice replaces them with a real API rather than rewriting them.

The gate asserts predicates, never golden host numbers: `pid > 0`,
`cpus >= 1`, `0 < total`, `0 <= available <= total`, `uptime > 0`,
`1 <= process count <= 64`, and that the process list contains the program's
own PID. `TestPhaseV1219_NativeRefused` pins K145/no-image for the native
target. `TestPhaseV1219_RuntimeWiring` asserts a metric-free program emits no
`karkain_os_pid(`.

### Three defects found and corrected during the slice

1. **Module filename.** `stdlib/os/metrics.kark` was not discovered by
   `import std.os`; renaming it to the canonical `stdlib/os/os.kark` made both
   engines resolve it. This is recorded so the next directory module does not
   repeat the guess.
2. **Empty line lost by `strings.Fields`.** The gate's `os_error()` assertion
   first saw seven fields because `Fields` dropped the final empty line; the
   gate now splits lines explicitly and pads, so the empty diagnostic is a
   real assertion.
3. **Self-PID evicted by the cap.** The process-list collector was capped at
   63 to reserve a slot for the current PID, but the same `-1` edit was
   applied to the self-add guard, so at 63 entries self was never added.
   Fixed by restoring the self-add guard to the full 64 bound. The
   self-containment assertion is what caught it.

All three were harness/runtime defects in this slice, found by running the
gate, not by inspection.

## 4. Non-claims and boundaries

- **C23 only.** Native has no OS process/metric syscalls and refuses by name;
  WASM K108-rejects the surface. No new platform decision was made.
- **No byte-identity** with the Go native backend; it cannot query the OS.
- **No KIR pin value measured or predicted locally.** `src/compiler` tables and
  the generated `osmetrics_runtime.kark` moved, so CI must measure
  `text=N verify=N` before any re-pin.
- macOS available memory and full process enumeration are limited as stated
  above; the v1.2.19 gate runs on Windows and Linux.
- No process control (`kill`, `spawn`, priority) — enumeration and metrics
  only. `stdlib/process`'s shell-backed wrappers are unchanged.

## 5. CI

Two dedicated steps are wired in `.github/workflows/ci.yml`:
*Run OS metrics runtime freshness gate* (`TestOSMetricsKarkFresh`) and
*Run v1.2.19 OS metrics / process enumeration gate* (`TestPhaseV1219_`). The
gate is a test file plus a CI step, per the repository rule.

## 6. First CI run — three failures, corrected against this baseline

CI run `45736831726` (PR #40, 2026-11-26) found three real defects. This is a
corrective change against the v1.2.19 baseline, not a new increment.

1. **Sphinx `-W` failed with four problems.** `stable-api.rst` gained the
   `std.os` row one indent level too deep (3/5 spaces became 4/6), producing
   `Bullet list ends without a blank line`, `Block quote ends without a blank
   line`, and a `list-table` parse error. The title underlines in
   `feature-matrix.rst` and `stdlib/os.rst` were one character short. All were
   corrected. Local Sphinx is unavailable on this host, so the fixes are
   structural; CI must re-run the docs job.
2. **Whole-tree KIR pin was stale.** CI measured `text=18517 verify=18517`
   against `18187`. Both assertion sites were re-pinned from that measurement
   only (+330 from the new `os_*` builtins and the generated
   `osmetrics_runtime.kark`). No local whole-tree verification was attempted
   and no value was predicted.
3. **The Linux gate parsed compiler diagnostics as program output.** `go test
   ./pkg/cli -run TestPhaseV1219_` failed with
   `not an integer "/home/runner/.../metrics.c: In function
   ‘karkain_os_process_list’:..."` because the Go engine inherits stdio and
   gcc warnings were captured together with the program's stdout. The gate now
   keeps stdout and stderr in separate buffers and locates the first run of
   seven consecutive integer lines before reading `os_error()`.

**Post-fix evidence:** `TestPhaseV1219_` PASS 22.153 s locally on both engines
with separate stdout/stderr and robust line location; freshness gates PASS;
`go build ./...` and `go vet ./pkg/... ./cmd/...` PASS.
