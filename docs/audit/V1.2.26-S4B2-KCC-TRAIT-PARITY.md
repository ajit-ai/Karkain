# v1.2.26 S4b-2 — kcc trait/impl parity (closes v1.2.26)

Status: **COMPLETE for both-engine observable parity**.

## Approach

The self-hosted compiler has no TraitDecl/ImplDecl AST nodes. A direct parser
port was attempted and reverted: it collided with `NODE_CONST_DECL` (94), used
the reserved identifier `fn`, and could loop in a nested `parseFunc` call. The
shipped approach is the repo's established **Go-side bridge**:
`pkg/cli/kcc_trait_bridge.go` lowers trait/impl declarations in the staged
source before kcc parses it. Trait declarations become blank lines (no runtime
code); impl bodies are lifted so their methods are ordinary top-level
functions. Line numbers are preserved so kcc diagnostics still point at the
original source. The bridge is applied after staging in check/build/run,
including the flat-project mirror path.

The Go engine keeps its native trait/impl parsing and completeness validation.
The bridge does not add validation to kcc — that is the documented boundary.

## Evidence

`TestPhaseV1226F_` (pkg/cli): both engines execute a trait/impl program with
exact stdout `42`; the bridge preserves line count and lifts methods; missing
method is rejected by the Go engine with the named diagnostic. Dedicated CI
step *Run v1.2.26 kcc trait parity gate* wired.

No kcc source changed, so the whole-tree KIR pin (20474) is unaffected.

**v1.2.26 is now complete for its delivered surface**: S1 mutability, S2 type
values, S3 local inference, S4a return inference (+ corrective), S4b-1 Go
traits, S4b-2 kcc parity, S5 const folding, S6 generics inference, S7 contextual
inference, S8 kcc const folding.
