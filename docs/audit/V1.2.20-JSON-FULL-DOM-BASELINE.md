# v1.2.20 — JSON full DOM

**Verdict: COMPLETE for the C23 path.** Both front ends can parse JSON into a
real `Value` tree, inspect node types, query nested paths, serialize with
correct escaping and report deterministic errors. Native and WASM remain
excluded by existing boundaries.

## 1. Measured baseline

- `stdlib/json/json.kark` had six flat string helpers: `json_get_field`,
  `json_get_int`, `json_get_bool`, `json_has_field`, `json_stringify`,
  `json_array_length`. No nesting, escapes, type awareness or quoting safety.
- `json_stringify` emitted raw text between quotes and could produce invalid
  JSON for quotes/backslashes/control bytes.
- `json_has_field` could false-positive when a quoted key appeared inside a
  string value.
- Existing gate `TestPhaseV121_StdlibPathAndJsonBothEngines` only covered the
  six flat helpers with a fixed golden.
- The generated preambles already provided all needed tree primitives
  (`make_map`, `make_array`, `map_set`, `array_push`, `array_get`, `map_get`,
  `karkain_len`, `karkain_mapKeys`). No new link library was needed.

## 2. What changed

### Runtime, single source of truth
- `runtime/json/c/karkain_json.{h,c}` implements five builtins:
  - `karkain_json_parse(text)` — recursive descent into a `Value` tree;
    objects = maps, arrays = arrays, scalars = string/int/float/bool, null =
    the `"__json_null__"` sentinel.
  - `karkain_json_type(node)` — `null`, `bool`, `number`, `string`, `array`,
    `object`.
  - `karkain_json_serialize(node)` — correct escaping for `"`, `\`, `\n`,
    `\r`, `\t`, control bytes; emits nested arrays/objects.
  - `karkain_json_get_path(node, path)` — dotted keys and `[index]` components.
  - `karkain_json_last_error()` — fixed-literal diagnostics with byte offsets.
- `runtime/json/embed.go` embeds the C sources for Go;
  `scripts/gen-json-runtime.ps1` generates `src/compiler/json_runtime.kark`
  for kcc (never hand-edited);
  `pkg/codegen/json_kark_fresh_test.go` (`TestJSONKarkFresh`) pins the mapping.

### Builtins and generation
- Five `json_*` names registered in the Go resolver, both kcc checker/sema
  tables and both C dispatchers.
- `needsJSON` prescan gates emission in the monolith path and `SplitResult.NeedsJSON`
  carries it into the shared split-flow header, avoiding the v1.2.17
  imported-module defect.
- `JSONLibFlags()` is an explicit empty seam; JSON uses libc only.

### Library surface
- `stdlib/json/json.kark` keeps all six legacy helpers and adds five wrappers
  with distinct names: `json_dom_parse`, `json_dom_type`, `json_dom_serialize`,
  `json_dom_get`, `json_dom_error`.

### Three defects found and corrected during the slice

1. **Preamble divergence.** The first runtime used Go-only `Value` fields
   (`arrVal`, `mapVal`) and `TYPE_BIGINT`/`TYPE_BIGFLOAT`. kcc's preamble uses
   different fields and a smaller enum, so kcc failed with undeclared
   constants and missing members. Fixed by using only the shared Value API —
   `karkain_len`, `array_get`, `map_get`, `karkain_mapKeys` — and only the
   common type constants.
2. **Wiring negative case.** The first "plain" case still imported `std.json`,
   which legitimately pulls the runtime because the module wrappers call the
   builtins. The negative case is now a no-import program.
3. **Native refusal case imported the module.** The first native test used
   the shared source helper, which always prepends `import std.json`. The
   limited native driver then refused an earlier `==` in a module wrapper,
   not the `json_parse` builtin under test. The native case now writes a
   no-import source and asserts the `json_*` refusal with no image.

All three were found by running the gate, not by inspection.

## 4. Non-claims and boundaries

- **C23 only.** Native and WASM have no JSON builtins; native refuses by name
  and WASM remains K108-gated.
- **No byte-identity** with the Go native backend; it cannot parse JSON.
- **No KIR pin value measured or predicted locally.** `src/compiler` tables and
  `json_runtime.kark` moved, so CI must measure `text=N verify=N` before any
  re-pin.
- Number handling follows C `strtod`: no arbitrary-precision JSON numbers.
- Duplicate object keys keep the last value, matching `map_set`.
- The `"__json_null__"` sentinel is a v1 DOM representation boundary, not a
  language-level null type.
