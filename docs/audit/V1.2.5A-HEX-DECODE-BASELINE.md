**Date:** 2026-11-22
**Branch:** `feature/v1.2.5a-hex-decode`
**Baseline:** `develop` merge `3d6d8f7` (PRs #20/#21: v1.2.4b trim corrective + KIR re-pin 16393)
**Classification:** new capability, smallest codec slice.

## 1. Prerequisites now satisfied

The earlier v1.2.5 attempt (reverted) failed because:

* the string-literal collector ignored `CallExpr` arguments, so a codec's
  literal argument resolved to print_int's `"-"` — **fixed in v1.2.4b**;
* trim's structural defects made the shared call path unusable — **fixed in
  v1.2.4b**;
* the rodata patch guard and emitter cursor disagreed when codec diagnostics
  were added. This slice must verify that coordination explicitly.

## 2. Scope

Implement `hex_decode_bytes(s)` in the kcc native driver:

* a native helper that decodes byte pairs arithmetically (no 256-byte table —
  Karkain cannot embed a byte-string literal containing 0xFF), allocates the
  result in the arena, and calls the existing runtime-error reporter for odd
  length and non-hex digits;
* the call path through `natEmitHexDecodeCall` using the existing `codecTemp`
  five-unit staging;
* scan, lowering, plan-kind, arena-sizing, rodata-interning and helper-emission
  wiring;
* a gate that executes the produced PE with exact stdout bytes, compares with
  the C backend, and asserts both error paths.

Byte-identity with the Go native oracle is **not claimed**: the oracle uses a
lookup table, kcc uses arithmetic. The contract is the decoded VALUE.

## 3. Error contract

* odd length → `runtime error: invalid hex string (odd length) at <file>:<line>`
* any non-hex digit → `runtime error: invalid hex string at <file>:<line>`
* exit code non-zero, no decoded value printed.

The native PE's stderr text may be empty on this host (documented
`GetStdHandle(STD_ERROR_HANDLE)` limitation), so the gate asserts the exit
status and the presence of the diagnostic text in the image, not the stream.
