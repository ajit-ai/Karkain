# v1.2.4b — trim corrective (baseline, before implementation)

**Date:** 2026-11-22
**Branch:** `feature/v1.2.4b-trim-corrective`
**Baseline:** `develop` merge `d048979` (PR #18: foundation audit + `indexRight` fix)
**Classification:** corrective change against the frozen v1.2.4 slice, not new scope.

## 1. Why this slice

The v1.2.5 hex-decode attempt inspected the committed v1.2.4 trim code and
found four structural defects. They are in `develop` and were not introduced by
that attempt. Because v1.2.4 shipped with **no gate**, none was caught.

## 2. The four defects (measured at baseline)

1. **`natNativeScanValue` — unreachable trim case.** The `CallExpr` arm has
   `return natNativeScanCall(expr, plan, line, fns)` immediately before the
   `if (callFunc(expr) == "trim")` block, so the codec case can never run. A
   `print(trim(...))` program is refused by `natNativeScanCall` as an
   unlowered builtin.
2. **`natNativeScanDecl` — trim nested inside the push branch.** The
   `if (callFunc(v) == "trim")` block sits inside the
   `if (callFunc(v) == "push")` block, so a value that is `"trim"` can never
   match `"push"`. A `let t = trim(...)` binding is refused.
3. **`natNativeScanReturn` — malformed block.** A line
   `if (nodeType(expr) == NODE_STRING_LIT()) {` is immediately followed by
   `if (nodeType(expr) == NODE_CALL()) {` with no body between them; the
   second `if` is therefore the body of the first, and the closing braces do
   not line up.
4. **Decl lowering — dropped array branch header.** The `else if
   (nodeType(v) == NODE_ARRAY_LIT()) {` line is missing, so the array-value
   emission body executes unconditionally inside the `NODE_CALL` branch and
   an array literal binding is mis-lowered.

## 3. Scope boundary

* Change ONLY these four control-flow/structure defects in
  `src/compiler/native_value.kark`.
* Do NOT add trim byte-identity with the oracle (the v1.2.5 attempt proved the
  rodata collector/emitter/patch sizing still disagree; that is a separate
  coordinated slice).
* Do NOT change the emitted bytes for any program that does not call trim.
  The existing corpus and KIR pin must remain stable apart from any measured
  AST-shape delta.

## 4. Gate to add

`pkg/cli/phase_v124_trim_test.go` — `TestPhaseV124_`:

* `TestPhaseV124_Print` — `print(trim("  hi  "))` executes as a kcc PE with
  exact stdout `hi\n`.
* `TestPhaseV124_DeclBinding` — `let t = trim("  hi  ") print(t)` prints
  `hi\n`.
* `TestPhaseV124_ReturnRefusal` — `return trim("x")` is refused by name with
  no image.
* `TestPhaseV124_ArrayBindingStillWorks` — `let a = [1, 2] print(a[0])`
  prints `1\n` (defect 4 regression).

Every case asserts kcc provenance, no silent Go fallback, exact stdout bytes
and a valid PE via the oracle's `ParsePE`.

## 5. Evidence and completion

Record exact `go test -run TestPhaseV124_` results here after implementation,
mutation-verify each fix, re-measure the KIR pin if compiler-source changes
move it, and add a CI step in the same commit.



Implementation results (2026-11-22)
===================================

All four defects were corrected in ``src/compiler/native_value.kark``:

1. moved the trim scan case before the unconditional ``return`` in
   ``natNativeScanValue``;
2. lifted the trim case out of the ``push`` branch in ``natNativeScanDecl``;
3. repaired the string-literal / call block in ``natNativeScanReturn``;
4. restored the ``NODE_ARRAY_LIT`` branch header in decl lowering.

Two shared prerequisites were also corrected, both proved by the gate:

* ``natNativeStrLitAppend`` now descends into ``CallExpr`` arguments, so a
  codec argument literal is interned (previously it resolved to ``"-"``);
* ``natNativePlanDecls`` now types a ``trim(...)`` binding as ``KindString``
  (previously it was typed int, so ``print`` loaded only the pointer).

Evidence
--------

* Pre-fix gate run: all four cases FAIL with the exact signatures recorded in
  section 2 (unlowered builtin; refusals; array-value crash; rodata patch
  guard).
* Post-fix: ``go test ./pkg/cli -run TestPhaseV124_`` PASS 60.833 s, all four
  cases green with exact stdout bytes and kcc provenance.
* Mutation: disabling the ``CallExpr`` descent in the collector reproduced the
  pre-fix output ``"-\\n\\x00\\x00\\x00\\x00\\n"``; restore to SHA-256
  ``A8353F68095FA2935D478569167F504A4F4E659B2576DBF71E3D7CB8F86E81DA`` and
  the gate passed again in 31.696 s.
* CI step *Run v1.2.4 trim corrective gate* added in the same change.

Boundary
--------

This is a corrective change, not byte-identity with the Go oracle for trim.
The rodata interning order for codec diagnostics is still not reconciled with
the oracle, which remains the blocker for the v1.2.5 hex-decode slice.


KIR pin status
--------------

The whole-tree KIR pin was NOT re-measured locally: ``karkain kir --verify
src/compiler/kir.kark`` hung on this host (the documented ~4 GB / whole-tree
verification class). Per the repository rule the pin is therefore NOT
predicted; the two assertions remain at their measured value 16204 and CI must
