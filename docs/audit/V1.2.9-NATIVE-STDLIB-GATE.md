# v1.2.9 - no-C `stdlib_v2` build-and-run (Condition 2)

Date: 2026-11-25
Branch: `develop`
Baseline: `a87e7cd` (Option B follow-up)

## 1. What is missing

Condition 2 of the v1.2.0 carried set requires a genuine `import std.*`
program to build and execute through the C-free native path. Before this
slice, the Go native backend could lower int arrays and basic string
expressions, but the stdlib modules were not exercised end to end.

## 2. Scope (Option B, owner-approved)

Scope is deliberately narrow: pure stdlib modules whose helpers take typed
string/int parameters — `std.string`, `std.crypto`, `std.encoding`. `std.io`
(file I/O) is deferred with a documented boundary. `std.collections`
array_* helpers take untyped params and are not lowered by the Go native
backend (param-kind inference from call sites is a kcc-side feature the Go
backend does not yet have), so collections is a documented boundary, not a
failure.

## 3. What works

- `examples/stdlib_v2_native/main.kark` (imports `std.string`, `std.crypto`,
  `std.encoding`) builds with `--target native-x86_64-windows --engine go`
  and runs with exact stdout bytes:
  ```
  5
  abcd
  00e0cba20c10cac449eb885a9926a4b646f0ac163ed7fbc5704d9d8a057ef44d
  cm91bmR0cmlw
  ```
- `split` / `str_split` (string arrays), `str_to_upper` / `str_repeat`
  (concat in loop), `hasKey` / `map_keys_of` are refused BY NAME with K145
  and write no image.

- `TestPhaseV129_NativeStdlibRefusals` — split + concat-in-loop refused by name.
CI step: `Run v1.2.9 native stdlib gate`.

## 5. Code changes (this slice)

`pkg/native/program.go`:
- Repaired deleted `return KindString, nil` lines in `retKindOfExpr` and `exprKind`.
- `BoolLiteral` → `KindInt` in both classifiers and `emitExpr`.
- String reassignment via `x = …` stores the (ptr, len) pair into the slot.
- `IndexExpr` on a string in `emitStr` lowers to a one-byte string view.
- Added `KindStringArray` with `kindUnits`/`kindName`/`paramKind`/`exprKind`/
  `retKindOfExpr` wiring and an `IndexExpr`-on-`KindStringArray` path in `emitStr`.
- `len()` accepts `KindString` and `KindStringArray`.
- `emitSplit` restored to a refusal by name (the tokenization implementation
  was unstable; refused rather than shipped half-working).
- `scanValueUsage` extended to detect split usage for heap-arena sizing.

## 6. What this does NOT claim

- No byte-identity with the Go oracle for native stdlib images (the gate
  compares executed stdout, not image bytes).
- No kcc native parity (kcc string params are a parked slice).
- `str_split` / `hasKey` / `map_keys_of` / concat-in-loop are refused by name.
- `std.collections` array_* helpers are a documented boundary (untyped params).
