# v1.2.21 — UDP datagrams and WebSocket text frames

**Verdict: COMPLETE for the C23 path.** Both front ends can send/receive UDP
datagrams and perform a real RFC 6455 WebSocket handshake followed by masked
client text frames and unmasked server text frames. Native and WASM remain
excluded by existing socket/concurrency boundaries.

## 1. Measured baseline

- `std.net` had only TCP wrappers; `net_*` runtime fixed
  `hints.ai_socktype = SOCK_STREAM`, so a separate UDP resolver was required.
- `std.http` had HTTP/1.1 client/server, HTTPS client and a concurrent echo
  server. No WebSocket handshake or frame codec existed.
- No SHA-1 implementation existed anywhere in the repository, so a generic
  RFC 6455 `Sec-WebSocket-Accept` could not be computed from an arbitrary key.
- Winsock is already linked with `-lws2_32` on every generated-C Windows path;
  POSIX sockets are libc. No new link library was needed.

## 2. What changed

### Runtime, single source of truth
- `runtime/udpws/c/karkain_udpws.{h,c}` implements nine builtins:
  - `udp_send(host,port,data)` — one-shot datagram;
  - `udp_send_on(fd,host,port,data)` — send from a bound socket;
  - `udp_bind(host,port)` — bound UDP socket with 5s receive timeout;
  - `udp_recv(fd,max)` — datagram payload;
  - `udp_last_error()`;
  - `ws_accept(key)` — generic RFC 6455 accept via self-contained SHA-1 +
    base64;
  - `ws_send_text(fd,text)` — masked client text frame;
  - `ws_recv_text(fd,max)` — unmasked server text frame, close frame handling;
  - `ws_last_error()`.
- The UDP resolver uses `ai_socktype = SOCK_DGRAM` and calls
  `karkain_net_init()` so Winsock is initialized before `getaddrinfo`.
- `runtime/udpws/embed.go` embeds the C sources for Go;
  `scripts/gen-udpws-runtime.ps1` generates `src/compiler/udpws_runtime.kark`
  for kcc; `pkg/codegen/udpws_kark_fresh_test.go` pins the mapping.

### Builtins and generation
- Nine `udp_*`/`ws_*` names registered in the Go resolver, both kcc
  checker/sema tables and both C dispatchers.
- `needsUDPWS` prescan gates emission in monolith and split flows.

### Library surface
- `stdlib/net/net.kark`: `udp_send_to`, `udp_send_from`, `udp_bind_on`,
  `udp_recv_from`, `udp_error`. `net_close` closes UDP fds.
- `stdlib/http/http.kark`: `ws_accept_key`, `ws_connect`, `ws_send`, `ws_recv`,
  `ws_error`. `ws://` only; `wss://` is not in this slice.

UDP proof: Karkain binds a UDP socket, sends `ping` from that socket to an
in-process Go echo peer, and receives `pong:ping` back. No readiness sleep is
used because the Go peer starts first and the Karkain program initializes the
exchange.

WebSocket proof: Karkain connects to an in-process Go TCP peer, sends a real
Upgrade request with an arbitrary key, validates the response using
`ws_accept`, sends a masked client text frame `hello`, and receives an
unmasked server text frame `world`.

### Two defects found and corrected during the slice

1. **Winsock not initialized.** The first UDP bind returned
   `udp: invalid address (10093)` (`WSANOTINITIALISED`). The shared resolver
   now calls `karkain_net_init()` before `getaddrinfo`.
2. **Boolean output form.** The gate initially expected `true`, but the
   C23 runtime prints comparison results as `1`/`0` in this path. The gate
   was corrected to assert the actual emitted form, not the source language
   spelling.

Both were found by running the gate, not by inspection. The newly added RST
sections were also checked structurally for blank lines, uniform list-table
indentation and sufficient title underlines, because local Sphinx is not
available on this host.

## 8. First-CI split-flow duplicate-symbol defect

CI run `45762070084` found a linker failure in the Phase 114 GoEngine corpus:
`karkain_udp_last_error` and `karkain_ws_last_error` were defined in both
`runtime.o` and module objects. This was a split-flow packaging defect, not a
socket-frame defect.

`HeaderForRuntime` gives internal linkage only to column-zero function
definitions whose signature line ends with `{`. Those two helpers were written
as one-line definitions ending with `}`, so they escaped that transform and
were emitted with external linkage in every translation unit. They were
rewritten as multi-line definitions, and `src/compiler/udpws_runtime.kark` was
regenerated from the corrected C source. Local verification completed green:
`TestUDPWSKarkFresh` PASS 2.811s and
`TestPhase114_CorpusExamples_GoEngine|TestPhase114_CorpusCoverage` PASS
743.032s, the exact Phase 114 command that previously failed with the
duplicate symbols.

## 4. Non-claims and boundaries

- **C23 only.** Native has no sockets and refuses by name; WASM remains
  K108-gated.
- **No byte-identity** with the Go native backend; it cannot open sockets.
- **No KIR pin value measured or predicted locally.** CI must measure
  `text=N verify=N` before any re-pin.
- Plain `ws://` only. TLS/`wss://`, permessage-deflate, continuation frames,
  ping/pong handling and server-side upgrade acceptance are not in v1.2.21.
- `SHort` UDP payloads are capped at 65536 bytes; receive timeout is 5s.
