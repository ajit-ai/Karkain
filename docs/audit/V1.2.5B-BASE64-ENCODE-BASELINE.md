# v1.2.5b - native base64_encode_bytes (baseline and evidence)

Date: 2026-11-22
Branch: feature/v1.2.5b-base64-encode
Baseline: develop c8cf7d2 (PR #24: v1.2.5a hex decode, KIR pin 16620)

## Scope
Lower `base64_encode_bytes(s)` in the kcc native driver: a helper with the
oracle's frame/offset layout (frame 72, outLen = ((n+2)/3)*4), group and tail
loops with `=` padding, the 64-byte alphabet interned in rodata, and full
scan/lowering/plan-kind/arena/helper-emission wiring. The contract is the
encoded VALUE, checked by exact PE stdout and C-backend differential;
byte-identity with the Go oracle is not claimed.

## Defects found during implementation
`natRodataRefOff(s, R9, off)` emitted a corrupted 10-byte sequence for an
extended register (natMovImm64Op(9) = 0xC1 with no REX.B). The alphabet pointer
now uses RCX, which is free in this helper. This is a latent limitation of
natImm64Patch for r8-r15, recorded here rather than silently widened.
