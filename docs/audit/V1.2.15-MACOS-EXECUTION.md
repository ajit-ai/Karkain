# v1.2.15 - macOS execution on macos-13 runner

Date: 2026-11-25
Branch: `develop`
Baseline: `c1af26f` (v1.2.13 native atomics platform decision)

## 1. What is missing

Mach-O images were structurally validated only (ParseMachO, MH_PIE, segment
set, rebase stream) — no Intel-mac runner existed to execute them. v1.2.15
adds the execution evidence.

## 2. What changed

- `pkg/native/phase_v1215_macho_exec_test.go` — `TestNativeMachOExec` mirrors
  `TestNativePE` using `runNativeMacOS`, executing Mach-O images and checking
  exact stdout bytes on darwin/amd64; skips honestly elsewhere.
- `.github/workflows/ci.yml` — new `native-macos` job (runs-on: macos-13)
  executing the gate. Free for public repositories.
- `docs/inventory/native-feature-matrix.json` — macos execution updated from
  "NOT proven anywhere" to "Proven on macos-13 CI runner".
- `docs/source/targets/host-targets.rst` — macOS row updated to execution
  evidence.

## 3. What this does NOT claim

- Apple Silicon execution (no arm64 native emitter yet).
- Byte-identity with Go oracle for Mach-O (structural validation only
  beyond execution).
- No compiler code changes. The emitter, PIE, rebase opcodes, and
  ParseMachO validator all pre-existed.

## 4. v1.2.16 CI scheduling follow-up

The job is retained, but its trigger is narrowed to the canonical push to
`main` (`if: github.event_name == 'push' && github.ref == 'refs/heads/main'`).
On PR #37 both the `pull_request` and `push` check runs sat **Queued** on the
macOS runner without starting, so they produced no evidence while holding the
board. PR and `develop` runs now SKIP; the execution gate still runs after the
owner merges to `main`, and the host-independent structural Mach-O gates stay
in the required `Test` job on every run. This is a scheduling condition, not
a weakening of the gate: the gate file, runner (`macos-13`), 25-minute timeout
and exact-byte assertions are unchanged.
## 5. v1.2.22 CI scheduling follow-up

The main-push-only condition still left a long **Queued** macOS check on PR
boards. The job is now ``workflow_dispatch``-only: PRs, ``develop`` pushes and
``main`` pushes SKIP honestly, and the gate runs when execution evidence is
explicitly requested. This is again a scheduling change, not a weakening:
the gate file, ``macos-13`` runner, 25-minute timeout and exact-byte assertions
are unchanged; structural Mach-O coverage remains in the required ``Test`` job.
