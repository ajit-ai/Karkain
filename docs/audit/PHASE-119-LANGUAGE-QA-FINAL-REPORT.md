### 3.1 Host environmental limitations (NOT defects — re-proven)

Both are the classes already documented in AGENTS (phases 95/96/99/101/
106/107/118), re-verified for Phase 119:

1. **`pkg/bootstrap` Stage-2 SEGFAULT (exit 0xc0000005).** The self-hosted
   `karkain-compiler1.exe` crashes while transpiling
   `src/compiler/main.kark` → C. **Proven non-regression:** reproduced
   byte-for-byte behavior on a pristine worktree at `1017068` (pre-Phase-119
   HEAD) — same test, same machine, same crash. Phase 119 touches no
   compiler/codegen semantics (version strings + docs + cleanup only).
   Stage-1 and every compilation/validation step before the transpile pass.
2. **Combined-CLI-gate OOM crash.** A single `go test ./pkg/cli -run
   "TestPhase114_|...|TestPhase118_|..."` invocation OOM-crashes on the
   ~4 GB host (documented class). Every constituent gate passes individually
   (table above).

CI (more RAM) runs the same gates monolithically in `.github/workflows/
ci.yml`.

## 4. Capability classification (for 1.0.0 stable)

Full authoritative staircase: `docs/source/status/scope.rst` (five buckets),
`docs/source/status/compatibility.rst` (guarantee vocabulary),
`docs/source/reference/stable-api.rst` (per-feature snapshot). Summary:

- **Stable Core** (regression-gated on both engines, 1.0.0): language core
  (variables/constants/functions/recursion/control flow incl. `while`,
  arrays, strings, maps, structs, enums/match, aliases, casts, slices),
  modules with `public` exports, C interop, assertions + runtime-error model
  (`runtime error: <kind> at <file>:<line>`, `stack:` dump, exit 1), stdlib
  v2 (`std.string/collections/io/encoding/crypto`), toolchain
  (check/build/run/test/fmt/lint/explain/clean/bench/config/target/workspace
  + LSP + package manager), self-hosted kcc default engine pipeline,
  numeric error codes (K001–K008, K100–K113 via `explain`), exit-code
  contract (0/1/2/3/4/6/7), conformance 59/59, probes 11/11, examples 49.
- **Experimental** (implemented/testable; may change): concurrency runtime,
  WASM `wasm32-wasi`, `karkain prof` profiling, SIMD lane types, NPU
  dispatch (`@target(npu)`), incremental cache, native linking/DWARF sections
  (container writer pending), `--target` cross-compilation (host-tuple only
  on this host).
- **Planned (no code exists)**: networking, web, database, GPU kernels from
  `.kark`, quantum, package registry / git fetches, `std.math/system/async/
  gpu` modules.
- **Known Limitations** (documented, deterministic): closures/`fn` codegen
  and `const` on both engines; GMP/big numbers; raw-pointer `alloc(T,n)`
  sizing; struct-in-array programs; bootstrap stage-2 + combined-gate OOM
  classes on ~4 GB hosts.
