# v1.2.18 — Concurrent HTTP server (C23 path)

**Verdict: COMPLETE for the C23 path.** Both front ends can serve multiple
HTTP connections concurrently through a canonical `std.http` entry point. No
new builtin was needed: the existing `spawn` machinery and the blocking
`net_listen`/`net_accept` builtins are sufficient once the server is written
as a named worker plus an accept loop.

## 1. Measured baseline

- The concurrency surface (`spawn`, `join`, `wait_all`, channels, actors,
  P0.2 `cancel`/`join_timeout`) is registered and emitted on both engines.
  `spawn` requires a **named top-level function** and generates one
  `karkain_run_N` wrapper per site; the runtime is C23-only
  (`runtime/concurrency/c/*`, embedded by Go and generated into
  `src/compiler/conc_runtime.kark`).
- The HTTP server helpers (`http_listen`, `http_accept`, `http_read_request`,
  `http_write_response`, `http_close`) are ordinary `.kark` wrappers over
  `net_*`. All existing server evidence was **single-connection**; no gate
  exercised `spawn` inside an accept loop.
- Native has no socket syscalls (v1.2.10) and WASM K108-rejects concurrency,
  so both are excluded by existing decisions. No new platform decision was
  made in this increment.

## 2. What changed

`stdlib/http/http.kark` gains two canonical functions:

- `http_echo_worker(conn)` — reads one request, writes
  `200 OK` with body `"hello " + req["path"]`, closes the connection.
- `http_serve_echo(host, port)` — binds the listener, prints
  `http server ready`, then loops `http_accept` and `spawn`s
  `http_echo_worker` for each connection.

The worker is a named top-level function because `spawn` cannot take an
expression or closure in v1.2.x. Tasks are detached; the accept loop stays in
`main`. No new builtin, no new runtime, no new link library, and no change to
the concurrency runtime sources.

## 3. Evidence

`pkg/cli/phase_v1218_http_server_test.go` (`TestPhaseV1218_`), driven through
the real CLI on both engines:

```
TestPhaseV1218_ConcurrentLoopback/go  PASS 16.50s
TestPhaseV1218_ConcurrentLoopback/kcc PASS 8.48s
TestPhaseV1218_RuntimeWiring          PASS 0.32s
ok karkain/pkg/cli 26.487s
```

The concurrency proof is deliberately not two sequential requests. The first
client connects and **sends nothing**; a serial server would block inside its
first `http_read_request` (5 s socket timeout). The gate then opens a second
connection, writes a request and requires the exact body `hello /second`
within a 3 s deadline. Only after the second response completes does it write
the first request and require `hello /first`. This fails a serial server and
passes only when each connection is dispatched to a spawned task.

`TestPhaseV1218_RuntimeWiring` checks that a program importing `std.http` and
calling `http_serve_echo` emits `static void karkain_run_` while a plain,
no-import program does not. The library itself contains `spawn`, so any unit
that imports it legitimately pulls in the concurrency runtime; the negative
case is therefore a no-import program, not another `std.http` program.

### Harness defects found and corrected during the slice

1. The first gate draft set `cmd.Stdout = io.Discard`. `os/exec` then creates
   pipe-copy goroutines, and the compiled program inherits the compiler's
   stdout; killing `karkain` left those goroutines blocked and `Wait()` never
   returned — the gate hit its 20-minute alarm in cleanup. Setting stdout and
   stderr to `nil` (direct null device) plus a 3 s `WaitDelay` fixed it.
2. The first wiring check used a `std.http` program as the "plain" negative
   case and correctly failed: importing the library now pulls the concurrency
   runtime. The negative case was changed to a no-import program rather than
   weakening the assertion.

Both were harness deficiencies, not compiler defects. The concurrency layer
itself passed its first run.

## 4. Non-claims and boundaries

- **C23 only.** Native and WASM have no sockets/concurrency surface here;
  they remain excluded by the v1.2.10 and K108 decisions.
- **No byte-identity** with the Go native backend; it cannot open sockets.
- **No KIR pin value measured or predicted locally.** `stdlib/http/http.kark`
  changed and is part of the assembled/verified tree, so the whole-tree KIR
  count moves. Only the CI *kcc whole-tree self-check (Phase 122)* job may
  supply `text=N verify=N`, and only that measurement may re-pin the two
  assertions.
- No TLS in this server slice (v1.2.17 is the HTTPS client); `http_serve_echo`
  is plain HTTP. No graceful-shutdown protocol, request router, middleware,
  keep-alive pool, or HTTP/2 — the gate uses `Connection: close`.
