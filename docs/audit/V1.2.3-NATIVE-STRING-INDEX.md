# v1.2.3 — Native string byte indexing

Status: **COMPLETE for the covered subset** (branch
`feature/v1.2.3-string-index`; increment 151 continuation, version v1.2.x).

## Measured baseline

On the current `develop` baseline (`541bde6`), this program was refused:

```karkain
func main() {
    let s = "abcd"
    print(s[1])
}
```

```text
error[K145]: native target: index target must be an array (got string 's')
exit 3
no image written
```

## What shipped

`src/compiler/native_value.kark` now treats `s[i]` with a string base as a
**one-byte string view**, not a byte integer:

- index is an ordinary integer expression (`s[i]`, `s[i + 1]`);
- result is `(base + i, 1)`, so no arena, copy or allocation is needed;
- bounds are `0 <= i < len(s)`, with the Phase-100 runtime reporter on failure;
- the kind string `"string index out of range"` is interned only when a string
  index exists, and its OFFSET is held in emitter slot 18 (a purely additive
  state-slot change in `src/compiler/native_emit.kark`);
- the same predicate drives scan, kind inference, print dispatch, binding
  emission and reporter detection, so they cannot disagree;
- nested bodies (`if`, `while`, `for`, `for-in`) accept `print(s[i])`;
- a `let b = s[i]` binding gets a two-unit string slot;
- array indexing remains byte-for-byte unchanged on all frozen gates.

## Gate

`pkg/cli/phase_v123_string_index_test.go`, pattern `TestPhaseV123_`, with its own
CI step *Run v1.2.3 native string index gate*.

Layers:

- exact stdout on executed Windows PE images;
- C-backend stdout differential (the Go native backend has no `s[i]`, so there
  is no ELF byte oracle for this construct);
- bounds cases: equal-to-length, above-length, negative, empty string and
  out-of-range in a loop, with the stdout prefix before failure asserted;
- refusals by name with no image;
- determinism and CI wiring.

Local result: **PASS**, 100.2 s.

## Corrective gate updates

1. `phase151a9f_string_test.go`: the row that pinned `s[i]` as refused was
   replaced by a still-refused int-position case (`print(s[0] + 1)`), because
   v1.2.3 now lowers the byte index itself.
2. `phase151d5_arrbounds_test.go`: Phase 1.3 rejects a CONSTANT out-of-range
   array index in the Go/C engine at compile time while the kcc native driver
   still emits the runtime bounds check. The gate now asserts those two measured
   contracts separately rather than forcing a false equality; the variable-index
   runtime reporter case remains.

## Non-goals

No string equality, slicing, trim, split, hex/Base64, SHA-256, `stdlib_v2`
proof, `std.net`, or version changes.

## Boundary

The Go native backend has no string-index lowering, so no Linux ELF
byte-identity claim is made for this construct. Linux and macOS execution of
this exact lowering remains structural in CI unless a native runner exists.

The same source was checked with `kcc check src/compiler/main.kark --engine go`
after the change: **PASS** with seven pre-existing unused-variable warnings.
The full gate is green locally, including real PE execution on this Windows
host.
