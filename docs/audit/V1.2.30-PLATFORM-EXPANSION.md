# v1.2.30 — Platform expansion (first slice: target model)

Status: **COMPLETE for the target-model decision**; no ARM64 code emitter or
Android/FreeBSD link proof is claimed.

## What shipped

- `pkg/target` gains `OSFreeBSD` and `OSAndroid`, with canonical short triples
  `x86_64-freebsd`, `aarch64-freebsd`, `aarch64-android` and `x86_64-android`.
  Conventional 3/4-component spellings (`aarch64-linux-android`,
  `x86_64-unknown-freebsd`) normalize to those short forms.
- ARM64 (`ArchAArch64`) was already in the model. This slice does **not** add
  an ARM64 native machine-code emitter.
- `FeaturesOf` reports 64-bit little-endian ELF for both new OS models, with a
  clang `--target` linker requirement (FreeBSD sysroot / Android NDK sysroot).
- ABI rules reject nonsense combinations rather than guessing: MSVC on
  FreeBSD/Android, GNU on Android, riscv64 outside Linux.
- `detectCompilerForTarget` routes both targets through
  `detectPosixClangTargetCompiler`: an explicit `CC` is honored, a same-machine
  host may use clang, and a foreign host without `CC` gets the deterministic
  `ToolchainError` — never a silent host fallback or a wrong-architecture image.

## Evidence

`TestPhaseV1230_*` in `pkg/target` pins parse/normalize, features and ABI
limits; `TestPhaseV1230_*` in `pkg/cli` builds a program for each foreign
target and asserts a toolchain error with no artifact. Dedicated CI step wired.

## Boundaries

No FreeBSD runner, Android NDK or ARM64 emitter is present in this repository,
so no execution or byte-identity evidence is claimed for these targets.
