# v1.2.31 — async/await (first slice: sugar over spawn/join)

Status: **COMPLETE for the covered surface** (single callee name, identifier await operands).

## What shipped

- `async f(args)` lowers in the Go parser to the existing `SpawnExpr` (`spawn(f, args)`).
- `await t` lowers to the existing builtin call `join(t)`.
- Both are parser-level rewrites, so sema, HIR, IR, C codegen and the native
  backend see only nodes they already understand. No second scheduler was
  introduced.
- For the self-hosted engine, `applyKCCBridge` rewrites the same sugar in the
  staged source before kcc parses it (`spawn(f, ` / `join(x)`).

## Evidence

- `TestPhaseV1231_AsyncAwaitLowerToSpawnJoin` (pkg/parser) pins the AST shape.
- `TestPhaseV1231_AsyncAwaitBothEngines` (pkg/cli) executes
  `func double(x) { return x * 2 }; let t = async double(21); print(await t)`
  on both engines with exact stdout `42`.
- Dedicated CI step *Run v1.2.31 async/await gate*.

## Boundaries

No `async func` declarations, no generic `await <expr>` operands (only
identifiers), no cancellation/`select!`, and no stackless coroutine transform.
The concurrency runtime remains the Phase 107 work-stealing scheduler. No kcc
source changed, so KIR pin 20474 is unaffected.
