============================================
Karkain v1.2.0 Verification Matrix
============================================

This matrix records what was actually verified for **Karkain v1.2.0** (tag
``v1.2.0``, peeled commit ``77d7069``). It is evidence-based: a row is not
marked ``PASS`` merely because the source contains an implementation. The
primary evidence is ``docs/audit/KARKAIN-V1.2.0-GA-QUALIFICATION.md`` and the
gates named in each row.

Status definitions
==================

``PASS``
   Directly verified by an executed test or a measured build result.
``PARTIAL``
   Some behaviour is implemented or verified, but coverage is incomplete.
``NOT VERIFIED``
   Implementation or test evidence is insufficient to claim correctness.
``NOT IMPLEMENTED``
   No implementation exists in the inspected release.
``BLOCKED``
   Verification could not be completed because of an identified blocker.

Local verification and GitHub Actions verification are distinguished below.
A red or unexecuted CI job is never reported as successful.

Reporter's note on CI
=====================

The v1.2.0 tag-triggered workflow (run ``43374786565``, 2026-11-14) had its
Build jobs rejected before starting because the account was subject to a
billing/payment restriction. It did **not** execute its Build matrix, and the
published checksums identify locally built archives. The three discovery /
informational jobs that appear red on later runs (B2 seed closure, increment
154 self-bootstrap, the one-off kcc whole-tree diagnostic) are non-gating and
their red status is the documented exit-143 runner-shutdown class — not a
compiler failure. None of them is reported here as a pass.
