=====================
Release Engineering
=====================

This page documents how Karkain releases are produced, how they can be
reproduced, and what the artifact model is. Nothing here invents a release
that does not exist: today the only supported installation is building from
source, and the binary distribution pipeline is ready but not yet published.

.. contents:: Sections
   :local:
   :depth: 1

Artifact model (what exists today)
==================================

.. list-table:: Release artifacts
   :widths: 34 66
   :header-rows: 1

   * - Artifact
     - Current status
   * - Source repository
     - The primary artifact. ``go build ./cmd/karkain`` produces the
       toolchain; all documentation and examples are in the repository.
   * - GitHub Releases (binaries)
     - :planned:`Planned` — the CI workflow (``.github/workflows/ci.yml``)
       builds the full target matrix on every tag and uploads artifacts; a
       tag-triggered release job publishes them with SHA-256 checksums.
       No tag has been cut yet, so **no binaries are published**.
   * - Source archives
     - GitHub auto-generates source tarballs/zip for every tag once tags
       are cut.
   * - Documentation
     - Sphinx-built and published from ``docs/source`` (deployed to GitHub
       Pages by ``.github/workflows/docs.yml``).
   * - Checksums
     - The release job computes SHA-256 for every archive and embeds them
       in the GitHub Release body.

Because binaries are not yet published, the 
:doc:`/getting-started/installation` page honestly instructs external
developers to build from source. No page advertises a download that does not
exist.

Reproducible release build
==========================

The toolchain is built from source with an unmodified checkout on the
release commit. Version identity is compiled in (a single constant in
``cmd/karkain/main.go``) and matches the ``VERSION`` file at the repository
root, so there are no hidden ``-ldflags`` version-injection hoops.

.. list-table:: Release build identity
   :widths: 30 70
   :header-rows: 1

   * - Property
     - Value / requirement
   * - Go version requirement
     - Go 1.21+ (CI uses ``actions/setup-go`` with ``1.21``; verified with
       Go 1.27 locally).
   * - OS
     - Windows, Linux, macOS, FreeBSD build hosts (CI supports a 12-target
       matrix).
   * - Architecture
     - amd64, arm64, armv7, i386, ppc64le, s390x (CI matrix).
   * - Build flags
     - ``go build -o karkain ./cmd/karkain`` (CI strips with
       ``-ldflags="-s -w"`` for release archives). ``CGO_ENABLED=0`` for
       cross builds.
   * - Version injection
     - None required: the version is a compiled constant
       (``Karkain Compiler v1.1.0``, ``VERSION`` = ``1.1.0``).
   * - Output artifact
     - A single platform binary named ``karkain`` / ``karkain.exe``.
   * - Checksum
     - SHA-256 computed over each release archive at publish time.
   * - Runtime dependency
     - A C compiler (GCC/Clang, or MSVC on Windows) is required on the
       *target* machine because ``build``/``run`` transpile to C before
       compiling natively.

Checksums
=========

Release archives carry SHA-256:

* Generated by the CI release job (``sha256sum`` over every artifact) and
  embedded in the release body.
* The local ``scripts/verify-install.ps1`` workflow verifies an installed
  binary against the current source tree before the smoke test.

Hygiene
=======

* Generated release artifacts live under ``releases/``, ``dist/``,
  ``.build/`` and ``artifacts/`` — every one is covered by ``.gitignore``.
* ``*.exe``, ``*.c``, ``*.c23``, ``docs/build/`` and temporary directories
  are ignored and must not be committed.
* Release scripts never force-push, never rewrite history, and never commit
  binaries.

Local release checklist
=======================

For a maintainer producing a local source release:

.. code-block:: text

   1. git checkout the tagged commit (clean tree).
   2. karkain --version                     # matches the tag
   3. go clean -cache                  # optional: clean build machine
   4. go build -o karkain ./cmd/karkain     # release binary
   5. ./karkain --version
   6. scripts/verify-install.ps1            # verify install + smoke
   7. python -m sphinx -b html -W --keep-going docs/source docs/build/html
   8. python -m sphinx -b linkcheck -W docs/source docs/build/linkcheck

CI (for a tagged GitHub release) does the same matrix build, packages the
archives with ``README.md``, ``LICENSE`` and ``VERSION``, computes SHA-256
checksums and publishes the GitHub Release.
