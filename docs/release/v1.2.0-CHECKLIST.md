## 2. Closure conditions — the release ships only if ALL hold

The eight conditions below are the **original contract**, recorded verbatim at
version open. They are deliberately **not edited**: an amendment that rewrote a
condition would change what the release promised, which is how a contract gets
quietly weakened. Status lives in §2.1, in the §4 carry-over list, and in the
§6 sign-off table — never in a reworded condition.

1. hello builds and runs with `gcc`, `clang` and `cl` all **absent from `PATH`**
2. `stdlib_v2` works in that same no-C environment
3. one `std.net` program builds and runs under the defined no-C constraint
4. native images are **byte-identical** between the Go compiler and `kcc` wherever the gate requires parity
5. `stage2 == stage3` — the self-hosted build is bit-reproducible
6. **no Go toolchain is required** for that self-bootstrap closure
7. `installation.rst` identifies Go as **reference-only**
8. the full version QA battery passes (units, Phase-114 corpus both engines, conformance, probes, every gate file, Sphinx `-W` + linkcheck, `verify-examples`, `install`/`verify-install`, `rc-journey`)

**These are not weakened to close.** A version is not closed as "green except X";
an unmet condition moves to the next version or to the carry-over list in §4.

### 2.2 Condition 4's limitation, and REL-001's disposition (2026-10-15)

**Condition 4 — read against its own wording, not against intent.** The verbatim
condition requires byte-identity "**wherever the gate requires parity**". The
gate is `TestPhaseD2_KnownNonParityIsStillNonParity`, and it does **not** require
parity for the one outstanding shape: it **asserts the difference** and fails if
the two images ever converge, with the message "That is progress: move it into
TestPhaseD2_KccAndGoEmitIdenticalImages". Six other shapes (`print(42)`, a single
local, two locals, a string literal, string concatenation, and the D5
bounds-diagnostic corpus) **are** asserted byte-identical.

So condition 4 holds as written, with one documented limitation:

| Item | Measured state |
|------|----------------|
| Outstanding shape | `array_index` only |
| Difference | kcc **1088** bytes, Go oracle **1096** bytes; residual is exactly **8 bytes**, the frame delta (`sub rsp,0x288` vs `sub rsp,0x290`) |
| Enforcement | asserted to DIFFER by the gate, so it cannot regress silently |
| Tracked as | NAT-001 / D6, status `deferred` (not selected) |

**This entry does not close the question, it surfaces it.** Reading a contract
narrowly to declare it satisfied is how a contract gets quietly weakened, so the
choice is an **owner decision and is not taken here**: either (a) fund D6 and
make `array_index` parity, or (b) formally accept the 8-byte non-parity as a
documented limitation of the release. Either way the *decision* is recorded, not
inferred from a pass.

**REL-001 disposition — investigated, unresolved, and NOT a release blocker.**
The intermittent `0xC0000005` in `kcc` is recorded as UNCLASSIFIED. Against the
release policy:

| Question | Answer |
|----------|--------|
| Does any closure condition name it? | **No.** Conditions 5 and 6 name the self-bootstrap pair, which is tied to **B2** (REL-002, the seed-closure runner deaths), not to REL-001 |
| Is it a mandatory blocker? | **No** — it is absent from the eight conditions and from the six-condition amended gate |
| Can it still affect the release? | **Yes, indirectly.** If it fires during condition 8 (the full QA battery), that run is not valid evidence and must be re-run. It is a risk to the *evidence*, not a condition in itself |
| Evidence so far | Five consecutive clean runs (`REL-001-CRASH-INVESTIGATION.md`): 466 s / 608 s / 473 s at a 64 MiB stack reserve, 487 s control at 2 MiB, plus two earlier runs. ASan proven **unavailable** on this toolchain (`cannot find -lasan`, MSYS2 UCRT64 gcc 14.2.0); the `-Wl,--stack,67108864` diagnostic verified in the PE header |
| Claimed root cause | **None.** A run that does not crash cannot discriminate between hypotheses, so the clean runs neither prove nor falsify the stack hypothesis |
| Next evidence-producing method | **WER LocalDumps** for `kcc.exe` (FullDump), left enabled until an occurrence yields a dump; then re-test the three falsified hypotheses against that dump rather than guessing again. **System-wide dump settings are unchanged and require explicit authorization to enable** |

If the owner prefers, condition 8 may be accepted with REL-001 documented as a
known unclassified reliability risk under the stated conditions. That is a policy
choice and is **not** made here.

**Why, from measured evidence rather than preference.** Both conditions are
blocked on capability that does not exist, so neither is a missing-evidence gap:

* The native driver lowers **no function call at all** — `src/compiler/
  native_value.kark` refuses any call by name, and `stdlib_v2` was measured
  refusing at its first call. Every `std.*` capability is a call, so Condition 2
  cannot build until native call lowering exists. That is a substantial new
  slice, not "the remainder of 152".
* `pkg/native` has no socket emitter, and `TestPhase152A_
  SocketCapabilityBoundaryRejected` proves `net_*` is rejected on the native
  target. Condition 3 additionally needs an architecture decision the owner has
  not made.

**Deferral is not a weakening.** The conditions are unchanged and recorded as
unmet, and §4 owns the v1.3.0 work. The prohibited move — the one this table
exists to prevent — is redefining either condition so it could be reported green
in v1.2.0.

**No claim of v1.2.0 release-readiness follows from this amendment.** Six
conditions must still be met, and B2 remains to be investigated independently.

## 3. Close ceremony (per increment, and once at close)

**Per increment:** code + gate + audit note + `AGENTS.md` record →
commit `develop` → merge `main` → push. The push fires `ci.yml`
(on `[main, develop]`) and `docs.yml` (on `[main]`), which builds
`sphinx -b html docs/source docs/build/html -W` and deploys GitHub Pages.

**At version close:** checklist finalised → full QA battery → version identity
(`VERSION`, both Go banners, three kcc banners, generated headers, LSP, every
version-pinning test) → docs flip (`roadmap.rst`, `compatibility.rst`,
`scope.rst`, `stable-api.rst`, `installation.rst`, release notes) → final
`develop` → `main` merge + push → **tag `vX.Y.Z` (owner-only)**. The tag is what
fires the `ci.yml` `release` job, which publishes the 13 archives +
`checksums.txt` + the GitHub Release.

## 5. Governance

* **A completed increment is frozen.** A later defect does not automatically
  reopen it. A corrective change must (1) identify the owning layer, (2)
  document why it is required, (3) preserve downstream behavior, (4) run the
  affected regression gates, and (5) be recorded as a corrective change against
  the frozen baseline — not as a new phase, and not by editing the original
  completion claim.
* **Evidence discipline.** A completion claim is only as strong as the check
  that produced it. A gate that can pass without comparing anything — for
  example one that skips when output is empty — is not evidence. Worked example:
  `docs/audit/PHASE-150-BASELINE.md` §12.
* **Scope freezes when a version opens**; new ideas go to the next version or an
  explicit carry-over list.
* **Heavy gates are never combined** in one command (the ~4 GB host rule).
